## 最终行为

| 场景 | 处理与反馈 |
| --- | --- |
| 检查发现新作品 | 元数据与持久子任务在同一事务登记，已发现的图片立即进入下载，不等整批画师检查完毕 |
| 检查、下载与转换并行 | 检查 1、下载最多 2、本地处理 1；逐项领取，手动任务优先，同一资产及转换输入互斥 |
| 日常检查已有作品 | 根据已登记事实发现缺项和来源变化，不遍历已核验原件的目录、大小或解码；本轮仍保留主站画师分页检查，不承诺增量 API |
| 本地原件缺失 | 具体媒体读取发现缺失／空文件后登记缺项；有界维护分批补齐，来源、原件、派生分别重试，不被正在检查的任务整体挡住 |
| 全量核验 | 设置中的手动核验按实际原件与预览逐项计数，完整库也报告核验数量，缺 GIF 等异常不能显示“无需处理” |
| 多页作品只下载首图 | 首图继续可读，图库、详情、流式共同显示整件作品原件总数、已核验与缺项；派生预览不能冒充完整原件 |
| 来源地址或时序变化 | 保留可用旧文件，记录待更新来源；仅匹配本次来源与意图的发布可清除待更新，旧响应不能覆盖新文件 |
| 下载失败或主站不可访问 | 现有本地内容保留，分别报告本地缺项、处理状态与来源原因；一次 404 不判定删稿，旧 GIF 缺原包仍由用户选择补回 |
| 暂停后续自动检查 | 已开始的画师名单及其保存任务继续完成；后续自动批次等待恢复，手动操作和本地处理仍可用 |
| 队列与进度 | 显示实际执行任务、阶段和正确单位；未知总量不编百分比，父任务等保存结案后才报告结果，失败不变成成功 |
| 大批任务 | 进度快照与依赖领取有界；等待中的父任务用 SQL 判断子任务是否结束，不反复加载 5,000 个子任务实体 |
| 切换存储目录 | 所有工作通道参与忙碌判断；候选实例在配置提交与旧实例关闭前禁止领取任务，失败保留原实例与租约 |
| 初始化失败 | 新库建表处于明确事务内，失败后不留下半套表；没有降低数据库持久性设置 |

公共读取增加兼容字段 `archive`、`processing`、`source_update`，保留原来的媒体与恢复字段；进度提供 `catalogue_revision` 与有界任务窗口。前端根据版本原位更新可见作品，不根据任务结束硬刷新页面，不重复触发收藏核对。

图库顶部自动接入当前筛选和排序下的新作品；已滚动或在其他页时出现“有新作品，查看”，由用户点开，不跳走。流式维持原范围，Logo 返回图库保留新作入口；纯补图不误报新增，首次进度轮询晚于旧空图库读取也能接回新内容。

大型浏览器抽样 JS 堆约 3.91～4.50 MB；这仅说明本次合成场景，不是长期内存保证。累计图片请求会随阅读新页增加，验收约束的是同时保留的范围与资源，不要求总请求数永远不增加。

前期发现并保留的失败包括：旧核验断言把正常核验当空任务、页面测试被未控制的后台维护竞争、目录切换对并行下载漏判和候选提前开放、初始化故障留下半套表。修正了实现与夹具职责，没有延长失败用例的期限、放宽成功标准或跳过检查。

首轮完整回归还发现自动检查与手动检查被同一个去重键吞并、排除未启动自动项后轮次不结案。修正保留自动批次的独立意图；任务轮次不等同于已启动画师批次，只有已实际启动的检查继续完成。测试在处理回调外核对成功结果，避免回调断言被任务系统记录为失败后，单凭 finished 状态误判测试通过。
