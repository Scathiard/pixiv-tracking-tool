# 前端超时与请求生命周期只读审查

基线：main / 6caefe6，公开版本 0.2.0，内部构建 20261004.2；2026-10-04。读取当前规则、三份主文档顶部、相关源码与测试。没有修改应用、真实配置或图库，没有打包，没有打开真实账号或用户页面。

## 已证实缺陷

- **原生超时直接泄露到产品提示。** `app/frontend/src/api.ts:2-3` 为每次调用生成 30 秒信号，重试共用该预算；`:11`、`:30`、`:33` 以 `throwIfAborted()` 原样抛出。独立 Chromium 空白页实测原生异常为 `TimeoutError`、`signal timed out`，且 `instanceof Error` 为真。`app/frontend/src/views/SettingsView.vue:27`、`:37` 直接显示 `failure.message`，日志与设置因此显示该英文。图库 `GalleryView.vue:114`、`:171`，导航 `App.vue:156`、`:192`，来源一览 `SourceStatusOverview.vue:31` 等同样直传。这是本地 HTTP 客户端超时，单凭文本无法判断是 Pixiv 远端、后台数据库还是网络阻塞。
- **日志读取没有取消、去重和旧响应拒绝。** `SettingsView.vue:23-32` 没有传入调用方信号或使用 `LatestIntent`，收起也不取消；`:32` 只检查是否已有日志，没有检查正在加载。提取现行脚本隔离实测快速打开→收起→打开产生 2 个并行 GET，较早响应随后覆盖较新结果，较新请求完成先把 `logsLoading` 变 false，旧请求仍活跃；`:121` 的刷新按钮只有这一布尔保护。该复现不等于它已经造成真实数据库阻塞，但其额外请求和显示竞争是确定缺陷。
- **设置离页仍留存读取，设置重试可竞争。** `SettingsView.vue:34-38` 没有信号、并发门禁或旧响应拒绝，`:113` 重试按钮没有禁用条件；`:109` 卸载仅设置 `stopped` 并清定时器，日志、设置、状态已发出的 HTTP 都没有被取消。隔离实测两个设置读取乱序返回时旧结果覆盖新结果；卸载后日志 GET 信号仍未 aborted，响应仍更新退役视图内部状态。离页后的状态变化未断言为用户可见画面，但 HTTP 留存已经成立。

## 已有正确边界与风险

- `interaction.ts:33-42` 的 `LatestIntent.begin()` 取消前一请求且用版本号防旧响应提交；图库 `GalleryView.vue:96-99`、`:150-155`、`:201`、`:241` 在筛选/翻页/重试及卸载沿用该机制；应用导航 `App.vue:126`、`:355-357` 也使用它；来源一览 `SourceStatusOverview.vue:17-21`、`:40-48`、`:56` 正确取消切换、后台及卸载请求。不能据设置缺口声称全部页面都不会取消。
- `TaskPanel.vue:78-82` 有 `polling` 门禁，`:108-112` 待当前请求完成后才安排下次，`:121` 卸载会 abort；当前任务轮询没有“每 1.5 秒累加一个卡住 GET”的代码路径。单次失败等待 30 秒，下一次按活动状态等 1.5/7/10 秒；事件只设 `refreshAfterPoll`，最多立即补一轮（`:68`、`:111`）。其错误提示用“状态暂不可得，正在重连”（`:29`、`:136`），不显示原生文本。
- `api.ts:4`、`:12-24` 仅 GET 的网络 TypeError 与 502/503/504 自动重试，最多 3 次，等待 350/1000 毫秒或最多 3 秒 Retry-After，整个过程共用 30 秒。TimeoutError 不会被自动重发，POST/PATCH/DELETE 不自动重试（`:62-63`）。所以真实 `/api/logs` 挂住直到客户端超时，本身不会在这同一 api 调用内制造 3 个重试。
- 共用请求层没有跨调用去重、并发限制或故障冷却；不同页面/轮询与多端可独立申请 GET。结合日志开关的已证实重复，这有放大后台压力的风险，但本次没有测出真实池压力或断言是后台根因。客户端 abort 不等于服务端同步函数已终止，受控真实 HTTP 证据见下节；SQLite 本身的终止与资源回收仍需另验。
- 设置 `pollStatus()`（`SettingsView.vue:84-91`）自身顺序安排 3 秒轮询，但没有统一 in-flight 门禁；登录/回调另可直接调用它（`:73`、`:80`），故重叠和离页后旧响应触发 `load()`（`:89`）是源码可达风险，本次没有专项运行此场景。
- `state/workCache.ts:5-7`、`:35`、`:45-50` 有意让共享详情 HTTP 不随单个消费者取消，只取消该消费者等待；`:11-16` 失效时清 flight 身份但不 abort 原 HTTP。它支持共享复用，并非自动认定缺陷，但无消费者的旧请求仍可占资源，需要在集中请求边界验收。画师检查状态 `ArtistsView.vue:115-116` 只防旧显示，没有传取消信号。

## 建议的集中边界与验收条件（候选，不代表已批准实施）

在 `api.ts` 统一分类 deadline、主动取消、网络错误、HTTP/业务错误，并保留安全的操作上下文；围绕已有 LatestIntent 提供页面读取与轮询的统一拥有者，负责关闭/切换取消、同类读取去重、旧响应拒绝和一次在途轮询。共享详情请求采用消费者计数与无人使用收尾规则，避免各组件自己补一组布尔开关。写请求保持不自动重放，超时提示应表述结果未确认并回读状态。统一边界不替代日志查询及后端资源占用修复。

验收至少涵盖：

1. 私有浏览器回放慢请求和慢正文；所有入口显示明确中文超时与对应重试入口，正常取消不报错，已载内容保留。
2. 日志快速收放、连续重试、离页及乱序响应；一个逻辑读取最多一个有效 GET，旧结果不覆盖新结果，loading 与当前拥有者一致；服务端继续执行量另记录。
3. 设置/status 与任务轮询在前后台、离页、登录回调和持续故障下，只有一次在途读取，失败冷却有界，没有定时器或退役页面继续创建请求。
4. 超时的 POST/PATCH 只发一次，明确区分“提交未确认”与“确定失败”，恢复后回读，不能提示原值必然不变。
5. 后台维护忙时，日志、设置、图库和任务各自有明确响应预算；测真实服务端的排队/查询完成量与回收，不只测 fetch abort 或合成小库。

## 同批脱敏证据

- `frontend-boundary-probe.mjs`：运行现行 api.ts，提取现行 SettingsView 脚本并用 ref/lifecycle/fetch 替身执行，没有挂载真实 Vue 页面。
- `frontend-boundary-result.json`：本次复现断言结果；Node 原生超时英文与 Chromium 不同，文件已明确标注。
- `chromium-native-timeout.py`、`chromium-native-timeout-result.json`：独立私有 headless Chromium 空白页确认确切 `signal timed out` 原生来源；无真实程序/账号页面。
- `server-disconnect-probe.py`、`server-disconnect-result.json`：生产 `create_settings_router()` 加真实 FastAPI/Uvicorn，127.0.0.1 随机端口，一次 stdlib HTTP GET；`processing_log` 只替换成 Event 读取替身，内部最多等待 1.5 秒；没有数据库。配置、鉴权和调度导入被替身隔离，未读真实 .env/token。外层 ASGI 观察器只记录 GET 的 `http.disconnect`，不取消或改变同步日志函数。

补充受控结果：日志函数在 39.297ms 进入，客户端在 194.544ms 读取超时并在 194.984ms 关闭；服务器在 195.068ms 明确接收到 `http.disconnect`，195.095ms 函数仍活动；主动释放 Event 后 195.122ms 才结束，Uvicorn 正常退出。断言全部通过。这证明 `settings_api.py:122-124` 的同步日志函数不会仅因为这个 HTTP 客户端断开而停止；不证明线上同一线程的多次栈必属同一请求，也没有测真实 SQLite 中断。前两次探针分别因启动预算过短、读取起点没有对齐到函数进入而未通过；第一次线程 join 未结束，随探针进程退出，第二次正常收尾。保留的最终 JSON 只对应此次成功运行，最终脚本用 entered 握手后才开始 150ms 读取预算，并断言服务器正常退出。

这些脚本与结果只是本轮诊断证据，不是已修复或 EXE/实体手机验收。仅新增本隔离目录中的文件，原有文件未删除。
