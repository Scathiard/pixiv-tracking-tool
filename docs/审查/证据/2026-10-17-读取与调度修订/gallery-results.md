# 图库状态读取：定向修订与验证

源码基线 `main / e68fcfb`；候选工作树 `codex/read-path-repair-20261017`。只修改任务赢家读取、作品状态读取段与对应测试；没有修改 schema、索引、数据迁移、父任务写入、版本或配置。

## 行为与兼容

- 先读取已有 `read_work_state`、资源汇总与维护账本；所有当前页作品仍实时读取活动任务。
- 没有原件缺项、本地派生缺项或来源待更新的作品无需历史失败；旧处理规则本来就不会为这些作品显示历史失败。
- 存在任一缺项且没有活动赢家时，保留完整历史赢家语义；先按父任务创建时间、更新时间归并窄摘要，再读取保留下来的 item 原因与排序字段。
- 相同时间仍按失败优先级、步骤位置、父任务 ID、直接/作用域、item ID 排序；作用域任务、默认版本、本地完整性、维护重试与恢复信息沿用原规则。
- 父任务开始、暂停或结束仍只更新共享父事实，没有扇出重写作品；没有删除或隐藏失败。

先前相关文件小回归为 19 项通过、2 项失败；两个失败位于已有规模用例 `test_window_reads_bound_entities_and_queries_with_5000_works_and_2000_pages` 与 `test_motion_card_reads_are_batched_for_current_window`，分别期待旧 SQL 起始文本与 compact 卡片加载 Derivative ORM。当前基线已使用 `SELECT s.work_id,s.value...` 和直接卡片投影，这两项旧断言与基线实现不符；未改宽断言、未以它们记为通过，也未另跑完整基线规模验证。最终 7 项定向选择没有包含这两个既有规模用例。
