# 版本形态窄投影：一次有限只读对照

结论：候选自然选择版本窄覆盖索引，确实去掉原 SQL 的随机宽版本读取路径，完整读取逻辑字节约 7.45MB；但本轮原 SQL 六次取消、候选两次取消/四次完成，不能宣告十二次预算与等价验收全部通过。它值得进入正确性验证和父会话候选判断，不表示长测卡死已修复。

## 边界和退出

- 唯一数据库为前轮冻结副本 `../b20261008-settings-index-comparison-01/run-01/copies/both.db`，开始/结束核对 size 与纳秒 mtime 一致，无非空 WAL；四子均以 mode=ro&immutable=1、query_only=ON 打开。
- 没有复制、DDL、ANALYZE、INDEXED BY、缓存调整、生产源码/现有测试修改或额外大库；两条既有索引定义未改。原索引对照报告/机器结果原位冻结。
- 正序原→候选、反序候选→原，四独立子进程，每个新连接首次+两次同连接暖读，共十二查询。未清 OS 缓存，逻辑 IO 不是物理盘 IO，首次不是冷盘。
- 进度回调保留4.5秒，父级单查询10秒硬截止；没有触发硬超时，进度中断单次实际最长5.6050秒（底层读取不是即时中断）。没有自行重跑。
- 父进程 exit=0（parent-exit-01.json）；四子 PID=27080/40248/60260/53740 都由父进程 wait 得到 exit=0，记录在 run-01/result.json；没有遗留探针子进程。

## 唯一候选变化与等价理由

在原 SQL 前加入：

```sql
revision_shapes AS MATERIALIZED (
  SELECT id,type,page_count FROM work_revisions
)
```

current_works 的 LEFT JOIN 改为 `revision_shapes.id=works.default_revision_id`，对应两处 COALESCE 引用 revision_shapes.type/page_count；其余字符串原样保留。完整 SQL/参数见 protocol.json。

WorkRevision.id 是主键，投影不改变版本行集合或数量；NULL/失效默认引用仍无匹配，COALESCE 仍从 Work 取 fallback，跨作品默认引用仍按 id 连接。全局成员集合、跨作品资产归属、suppressed 选择者、最终 owner 过滤、动图/页面限制以及五统计 CASE/gap 均未调整。本轮未另外创建异常夹具，该边界需要后续既有语义测试验证。

## 实际计划差异

| 路径 | 现行 SQL | 候选 |
| --- | --- | --- |
| Work | SCAN works USING COVERING INDEX ix_works_settings_shape | 相同 |

| 默认版本连接 | 直接版本主键连接 | SEARCH revision_shapes USING AUTOMATIC COVERING INDEX (id=?) LEFT-JOIN |

候选无 INDEXED BY 提示，也没有将新增版本索引改成唯一；顺序扫描窄版本索引和临时形态表连接使现有两条索引均被实际选用。不存在借建索引预热解释候选覆盖计划的混杂，因为本轮没有建索引。

## 全历史版本边界与未测内容

- revision_shapes 会扫描全部 WorkRevision，而非只扫当前默认版本；固定 08 夹具为约15k作品/15k版本，不覆盖多版本密集库。
- 对总版本数 R，覆盖索引顺序读取/临时行生成至少 O(R)，内存或临时存储占用随 R 增长；为 id 连接建立自动临时索引可能有 O(R log R) 的构建成本，随后 W 作品按 id 查询。最终是选用窄顺序读取/临时连接，代替 W 次宽行随机读取，不是把版本成本变成与历史无关。
- 大量旧版本时，工作集、临时索引、可能的临时落盘和 CPU 成本需要另行有界验证；本轮没有扩大历史夹具或推算一个未验证的最大版本数。
- 初次候选仍两次触及原预算，完整正序第三读也2.45秒而反序约0.30秒；不能只拿暖读宣告原用户体验门槛已解决。
- 后续需要既有异常语义/HTTP/预算回归、生产入口验证及实际持续负载；本轮不代替它们。未新增结果缓存/持久统计表，也不延长时限或为仪器 derivatives.count 增加索引。
