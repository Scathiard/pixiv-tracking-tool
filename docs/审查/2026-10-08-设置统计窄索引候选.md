# 设置统计窄索引候选

状态：2026-10-08 用户批准“允许实现、隔离验证，通过后备份应用真实图库”；两条索引和语句内窄版本投影已实现，专项结果与局限如下；完整回归及持续验收待完成。真实图库未操作，下列范围及验收条件保持。

## 为什么需要追加

- 基线 `9eb03bc` 的独立后台整理已完成实现及专项回归，但持续验证在 9191.125 秒失败；七个设置请求共用的聚合查询耗时 4.498 秒并被预算中断，其余当轮 HTTP 成功。详情见[本轮记录](2026-10-04-并行任务与本地读取修订.md)。
- 随后在同一份已关闭的合成库上只读对照：改写成员资格判断、将连接缓存从默认值增至 32 MiB，均未获得稳定墙钟收益，暂不采用。
- 原统计每次完成时，进程记录约 248,549,376 字节的逻辑读取；这不是物理硬盘读量，也不能据此诊断硬盘故障。
- 当前查询虽然只选作品 ID、默认版本、类型和页数，仍需访问包含长简介、来源 JSON 的作品及版本记录；现有索引没有同时覆盖这些字段。
- 目标是减少为取得几个统计字段而读取宽记录的成本；不是延长超时、缓存旧统计结果或改变存储位置。

## 具体候选

仅增加以下两条非唯一、可重建的查询索引，保留已有索引、表、字段、记录和文件路径：

```sql
CREATE INDEX ix_works_settings_shape
ON works(default_revision_id, pixiv_illust_id, type, page_count);

CREATE INDEX ix_revisions_settings_shape
ON work_revisions(id, type, page_count);
```

`works.id` 是 INTEGER PRIMARY KEY，可由普通索引携带的 rowid 取得；版本索引则显式包括文本主键。候选意图是让形态投影直接从索引读取，避免回到宽记录，依据为 [SQLite 覆盖索引说明](https://sqlite.org/queryplanner.html#covidx)。是否实际选用及收益大小仍须隔离建索引后的执行计划与测量确认，不能预先认定通过。

- 统计口径不变：默认版本与旧无版本记录、跨作品资产引用、隐藏／抑制、空路径、缺项、动图和重复引用仍按现行语义处理。
- 作品、版本和资产的事实仍实时读取，不增加结果缓存或新的统计表。
- 保持 `0003_revisions` 记录格式、端口、目录、令牌和 FULL 保存；旧程序可忽略新增索引读取同一库。
- 不为验收驱动收尾时的 `derivatives.count` 单独增加生产索引；该诊断读取与真实 HTTP 失败分别记录。
- 索引占用空间及有关字段更新的写入代价必须测量；只保留有实际收益的候选，不顺手添加其他索引。
