# 持续分卷与日志时间戳

- 基线：`main / c7a46bd`，日常 `0.2.0 · 20261011.13`；本轮候选 `20261012.1`，用户明确要求修好打包启用、不过度测试。
- 已确认：旧详细日志在 2026-10-11 14:44 达 512 MiB 后停录，同一实例后续超时没有完整现场；普通日志仍有约 4.55 秒的图库超时摘要，但无时间戳，无法精确对应用户操作。
- 范围：只修日志分卷、时间戳和启动截断；不调整业务调度、读取时限、图库格式、配置、令牌或账号任务。BUG-108 整体超时继续开放。

## 实现

- 诊断按约 64 MiB 一卷持续续写，文件为 `diagnostic-日期时间-进程-运行标识-part0001.jsonl`、`part0002` 等。每行 JSON 保持完整，单条超大记录可越过软分卷大小；没有总量停录开关。
- 每卷边界含 UTC 毫秒时间、运行／构建标识、卷号、前后文件名和邻接序列；业务记录的序列连续，跨卷的请求／任务关联不变。旧文件不覆盖、不删除。
- 继续使用有界异步队列和现有探针。磁盘或权限导致真实写入失败时，普通日志明确记录安全错误类型；不输出异常正文，不假称诊断仍运行。
- 普通 `tracker.log` 保留全部旧字节，新增每行格式为 `[2026-10-12T02:10:37.444+08:00] 内容`；按线程拼接 print 分段，完整行用共享锁追加，支持 logging／traceback／flush。未完成行主动 flush 后被其他线程插入，后续片段会另起带时间戳的新行。
- 取消启动时超过 1 MiB 截掉前半的旧行为。此次未增加自动清理、压缩或全局采样政策；旧日志由用户决定处置。
