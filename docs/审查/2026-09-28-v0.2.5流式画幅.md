# v0.2.5 流式画幅与共享作品信息

状态：两项获批布局调整已实现、验证并交付到 `release/v0.2.5/` 与 `D:\PixivTracker`；退出旧版托盘程序后即可打开新版，用户体验与实体手机待验收。缓存／收藏 BUG-055～060 只完成审查，未在本版修复。

## 实现

- 基线 `main` / `f31b122`，实现提交 `067f83985ce42db320ada24b87c602619d99f76c`，开发分支 `codex/v0.2.5-flow-layout`。
- 流式多页作品只在第一页显示标题、作者与分级；每页保留页码和放大，底部仍显示当前作品，可从作品中途识别当前位置。
- 流式图片由浏览器按实际可用宽度与自然比例决定高度，移除实际容器的固定高度和 1600px 长图限制；宽高属性预留未知／未载入时的空间，解码后以自然尺寸更新。
- 按图片页虚拟化和最多 120 页元数据窗口保留，普通详情继续使用原固定阅读区。仅调整 PageReader、MediaImage 与相应 CSS，后端逻辑未改。
- 数据结构仍为 `0002_client`，v0.2.2～v0.2.4 图库直接通用；没有真实数据迁移、配置／令牌修改或账号操作。

主会话审查后，将第一版按 CSS 常量推算的实际高度改为浏览器自然排版，避免滚动条宽度与媒体查询断点不一致；随后重跑前端与浏览器检查。EXE 首轮在入场过渡期间测量横向布局而停止，最终检查先等待过渡结束，仍保留无横向溢出与 2px 比例误差要求，第 2 轮通过。

源码浏览器由执行子代理运行，主会话复核变更、截图与边界；主会话另行驱动打包 EXE。原始材料保留在 `.devtools/test-runs/v025-*`，全部为合成媒体和隔离图库。
