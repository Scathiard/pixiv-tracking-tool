# 0.1 与 0.2 存档实现对照

状态：源码对照与设计评估；下载请求修复及单件冲突隔离属于已授权缺陷修复，本文中的调度、状态及模块调整为候选，不据此实施大重构。

## 判断

**保留 0.2 的逐资产记录、文件发布恢复和本地阅览，重做日常检查与存档调度的组织方式。** 0.1 的下载实际依赖成熟工具提供兼容行为；0.2 增加了安全记录，却替换了这条成熟链路，又延续并放大了“先全部清点、再开始下载”的等待成本。

本次新图 403 是替换下载器遗漏客户端标识；静态与真实单页对照已确认。另有单件资料冲突截断画师发现、完整性和预览状态混用等问题，不能以“页面变流畅”“增加恢复表”或单纯的测试数量宣称接手完成。

## 两版的实际行为

## 已证实的问题与风险

1. **新图来源拒绝：** 同图默认 Requests 标识 403，Pixiv 客户端标识 200，再恢复默认又 403；补回标识后，下载、校验、发布、缩略图和读取通过，见[兼容修复](2026-09-30-原图下载兼容修复.md)。
2. **单件冲突中止后续发现：** `_save_remote_work` 在旧页数／类型／画师冲突时抛错，异常捕获在画师分页循环外；后续页和下一作品类型不再消费，下一次可能重复停在同一件，后续作品尚未入库，维护无法补齐它们。
3. **日常检查过重：** `check` 完成远端列表后 `_work_ids` 选中所有作品，`_plan_work` 对非维护任务检查所有资产；已核验资产有文件属性缓存，却仍需逐件查询和访问文件，不能称作只处理新作与已知缺项。
4. **作品完整性与首图可看混用：** `library.py:55-59,315-331` 首图与缩略图可读便覆盖作品级等待状态；第 2 页仍失败时，卡片可能 ready 而详情 waiting，`test_gallery_card_fallback.py` 固化了这个表现。
5. **本地原件与远端更新混用：** `archive.py:279-281` 对 source_changed 一律不核验，手动 verify 也可能把仍保留的旧原件称作缺失；本地完整和远端有新版本应分别表述。
6. **恢复规则分散：** 资产状态、任务结果、维护 JSON、来源元数据与页面覆盖各有条件，`archive.py` 还跨模块调用维护私有 `_project`；这些记录各有用途，但不能各自推导一份互相覆盖的最终状态。
7. **长写事务风险：** `media.py:237-271` 在数据库写事务内计算文件散列和移动文件；大文件可能延长收藏确认等其他写入的等待，尚未测得实际延迟，不按已证实故障报告。
8. **测试的接缝不够真实：** 旧打包冒烟预置原图再核验，绕开实际下载器；本轮改成由打包程序实际下载合成图片后核验发布，并保留有限真实来源对照。

`Work.downloaded_at` 当前在发现时赋值，界面已确认名称为“最近存入”；按元数据入库时间筛选可成立，但该字段不能用于宣称原件已下载，不能不经产品定义就把此项列为新故障。

## 应该怎样组织

目标流程保持直接：**检查画师 → 每件作品落库并登记明确缺项 → 下载原件 → 核验并发布 → 生成阅览文件。** 每一步的持久交接可恢复，新图能在其他画师还在检查时开始保存。

| Module 与 Interface | 内部负责什么 | 不向调用者转嫁什么 |
| --- | --- | --- |
| 发现：检查一个已固定批次 | 远端分页、逐件保存、隔离资料冲突、为新作／已知缺项交接处理项 | 不在日常检查中体检全部已有原件；不因单件冲突截断画师 |
| 下载：取得一个明确原件 | 经过兼容验证的请求、限速／冷却、有限重试、临时文件与下载结果 | 界面和画师逻辑不自行拼头、刷新 token、猜成功；后备图不冒充原件 |
| 存档：发布一件已核验资产 | 校验、保存意图 revision、发布日志、恢复与状态提交 | 下载和生成器不直接把文件写成最终成功，不互相实现发布规则 |
| 调度：提交意图与查询处理进度 | 持久待办、相同目标去重、暂停批次、重启、优先级与失败退避 | 一份明确任务状态；维护只提交缺项，不另当任务执行器或最终状态裁判 |
| 图库：读取本地事实 | 分开提供预览可读、原件完整、主站可获取、当前处理状态 | 页面不根据首图／百分比推断完整性，不连接主站决定本地可用性 |

执行通道候选为：检查 1 条、原件下载最多 2 个受控工作者、本地预览 1 条；共用数据库与发布机制，API 和图片各自共享限速，禁止无限创建线程。进度浮层显示当前任务真实单位及数量，其他通道用简短说明；不要求全轮检查完才能有可靠反馈。

逐件存档计划优先复用现有 Work、Asset、OperationItem、发布记录；先证明正确交接，再讨论是否需要结构调整。不会先新建另一套兼容层、独立服务或迁移图库。若结构变更确有必要，备份、升级、失败恢复与 EXE 同版交付，按现有授权规则确认具体范围。

1. **当前缺陷修复：** 补回图片请求兼容标识、单件冲突继续检查、真实原件至可读页面；单图、多页、ZIP、失败和重启回归，保留旧内容与独立本地包。
