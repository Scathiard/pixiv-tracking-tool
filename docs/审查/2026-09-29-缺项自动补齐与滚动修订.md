## 问题与处理

| 问题 | 已核实的原因 | 本轮处理 |
| --- | --- | --- |
| 宽屏图库两侧留白滚轮无效 | 2560px 下外侧留白命中滚动容器之外的布局元素；普通桌面宽度不产生这段留白 | 滚动区域铺满内容区，卡片与控件仍保持原来的居中宽度；详情、流式在已测尺寸未复现，不加全局滚轮转发 |
| 缺图长期停在占位 | 缩略图由页面提交，缺首图被排除，短期轮询结束后没有恢复责任方 | 后台按数据库已知缺项分批补齐；页面只读取可见窗口状态，完成后更新图片，保留位置 |
| 下载失败变成“尚未下载” | 缩略图清点把已有 failed 及错误原因覆盖为 missing | 缺文件观察不抹掉上次下载失败，下一次实际处理才更新结果 |
| 限流处理不一致 | HTTP 429 在正文处理之前抛出；正文限流曾阻塞执行数分钟；请求时间写到错误的实例字段 | API 与图片分别节流，HTTP／正文限流进入对应共享冷却，保留状态与等待信息，交给后续任务恢复 |
| 收藏失败却提示结果不确定 | 当前两条历史记录为 failed，却共用不确定文案，未保存明确失败的细节 | 明确拒绝显示安全原因；超时、限流或查询不明保留最后事实。历史记录仅修正展示，直说旧记录未保存原因 |

详情或流式的已载入图片、图库卡片不会因为后台刷新失败而被清空；图片曾加载失败、补齐后仍使用同一路径时，也能恢复显示。没有真实 Pixiv 请求参与本轮隔离验证，不能据此认定先前真实图片的 401／403 原因已经解决。

## 补齐规则

- 程序后台定期处理已登记的缺失、失败或损坏原件，以及可由本地原件生成的预览和缩略图；不通过遍历文件库发现新缺项，不把未知旧文件批量核验。
- 已有路径但尚未核验的旧首图／GIF，可以仅核验本地派生所需的输入；其他未知页面不读取、不据此联网。
- 复用现有单写入任务队列，日常任务优先；暂停后续自动检查不阻止已入库内容恢复，离线仍可生成本地派生文件。
- 每类候选分别分页，每次最多读 128 项；本地有积压时每 10 秒最多提交 8 件，联网补齐每分钟最多提交 1 件。等待中的旧项不阻挡后续可处理项。
- 原图与本地派生分别退避；某页远端被拒绝不妨碍同作品已有首图生成缩略图。重试记录持久保存，重启不会清空等待时间。
- 401／403 等拒绝先等待 15 分钟，连续失败逐步延长至 1 小时、6 小时和最多一天；限流参考服务端等待信息。间隔是本程序的保守策略，不是 Pixiv 官方配额。
- 保留旧动图“用户选中后才补原包”的决定，删除阻止记录优先；成功项不会因为补齐其他页而重新逐页核验。
- 缺项完成后原位刷新。已排队、等待重试与完成保持区分；后台读失败不清空已加载内容，不循环弹提示。
