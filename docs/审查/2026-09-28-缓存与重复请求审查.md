## 额外性能开销

以下已确认存在开销，但没有测得其在真实图库中的卡顿贡献，优先级低于上述显示、错误操作和浏览阻断。

- **空闲进度轮询：** 面板隐藏且无任务，4.8 秒内仍取进度 3 次；实现约每分钟 40 次／前台标签页，空闲一次快照约 7 条本地查询。宜空闲退避、提交任务时唤醒；这些请求不访问 Pixiv。
- **媒体路径线性查询：** `Runtime.media_path` 每次图片请求都查询头像／原图／派生图路径，相应路径列无索引。44,992 条合成原图中，100 次靠后路径 SQL 共 92.61ms；只在合成库加索引后为 0.37ms。这是纯内存 SQL 对照，不是单张图的实际延迟。索引属于结构调整，若采用，须同版提供兼容升级与回退。
- **流式范围重复计算：** 每取 40 页窗口都重新排序并累计整个筛选范围，再查总页数。15,244 件×3 页合成 SQL，在不同位置各执行 10 次窗口查询为 66.62–71.06ms；尚不含总数、ORM 和媒体读取。可考虑按固定范围复用页边界，必须正确处理筛选、本地删除与更新，不能缓存失效后错位。

## 修复应守住的边界

- 上次**同账号已确认**的值用于即时显示，正在自动核对不抹掉旧事实；缓存时间与状态保留在现有悬停／无障碍说明中。
- 用户点击后的新目标仍须回读确认才改变；超时、未知字段、失败、账号不明、换号和重启未决写入不能被缓存期限跳过。
- 未验证的旧版缓存和另一账号的值不能冒充当前账号已确认事实；先隔离账号范围，再优化缓存。
- 普通、流式、图库应共用一套按作品和账号管理的事实；持久表已有 source、account_id、confirmed_at，首批收藏修复不必迁移数据库。
- 自动核对与用户明确“同步收藏”区分，后者可强制回读；缓存查询与轮询不应触发新的收藏／取消写入。

实施候选与授权状态见[路线图](../功能路线图.md)。本报告不等于缓存修复的开工批准。

## 覆盖与限制

检查了当前 Vue 图库、普通／流式阅览、收藏、画师、筛选、设置、任务状态、媒体路由和对应库查询。画师最近作品与关联资源采用批量查询；筛选／画师请求有代次保护，图库 480 件、阅览 120 页及位置记录上限存在，未发现同级的无界挂载问题。

收藏和账号场景使用当前实际前后端及合成数据库；轮询使用实际 TypeScript 模块和可控计时器；图库失败／切换请求使用当前已交付前端配合合成接口；HTTP 使用实际路由及合成路径适配；SQL 为独立合成微基准。没有真实账号写入、真实图库修改或本轮 EXE 性能测量，不将这些结果冒充真实手机与用户验收。
