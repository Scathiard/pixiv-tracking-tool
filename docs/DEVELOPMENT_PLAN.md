## 四、架构注意事项

- SQLite 单文件，多线程 WAL 模式
- 无前端框架，Jinja2 SSR + 原生 JS
- 后台重任务由单一 `JobManager` 串行调度；gallery-dl 内部下载 worker 保留
- 图片 `FileResponse` + `loading="lazy"`
- CSS 变量 `:root` 统一管理主题色
- 筛选状态全走 URL 参数，前端 AJAX + pushState
- Fragment 模板（`gallery_fragment.html` / `artist_fragment.html`）供 AJAX 无限滚动
- `illustration_tag` 独立表 + 索引，JSON tags 列保留兼容
- caption HTML 文件负责展示，DB 现有 `caption` 列从 v0.1.1 起只保存获取状态
- v0.1.3 若实装 Chart.js，必须本地引用（`static/`），不走 CDN
- 备份/还原仍是待规划功能；若实装，必须异步执行并在开始前估算体积
- IPv4/IPv6 默认双栈监听并共用端口 `1919`；不增加登录/配对，依靠局域网来源边界与透明 CSRF 防止跨站写入
- 数据目录迁移只复制到空目录，验证后原子切换；旧目录默认保留，`.env` 始终位于 EXE 同目录
- `src/version.py` 是版本号唯一来源；release 产物通过 `release/vX.Y.Z/` 交付
