## v0.1.2 执行包：存档可靠、反馈可信

**依据与状态：** 2026-09-26 用户要求落实方案，并另行批准数据库结构与转换代码的隔离实现；2026-09-27 又批准真实图库转换和新路径启用。当时的开发基线为旧 `master` / 3705098、v0.1.1；两个候选版本与 v0.2.1 切换版位于独立分支和本地 release，旧包未覆盖。真实图库已转换并离线启动；联网功能尚未验收，v0.2.1 视觉体验已被用户判定不通过。

### 用户问题与范围

处理缺页仍报完整、失败仍报成功、原包丢失、暂停／停止混同，以及总进度像指示灯、状态和结果难以追溯的问题。覆盖现有添加、检查、刷新、补下载、单件下载、校验与本地整理入口，先接回现有界面。Vue 阅览界面与新工具不进入本版。

### 业务核心与数据规则

1. 画师身份独立于追踪；本地浏览、隐藏、删除不依赖登录。停止追踪保留文件、元数据与本地选择。
2. 自动检查任务开始时固定本批画师名单；中途暂停不改变该已启动批次，尚未启动的自动批次读取最新政策；手动操作不以自动暂停状态拒绝执行。
3. 按作品与页号／原包记录资产、路径与核验状态；缺页、空文件、损坏和预览失败分别报告，非空 file_paths 不等于完整。
4. 动图 ZIP、帧顺序和时长长期保留；GIF 发布前核验可读性及时序，失败保源。旧 GIF 不删除，缺原包清单由用户选择补齐。
5. 下载与转换先暂存、再校验发布；文件发布、DB 更新和删除决定有恢复记录。重启核对未完成项，成功项不重复下载，发布前再次检查删除阻止记录。
6. 按操作目的、目标和范围去重；不同目的不可因画师 ID 相同而互相吞掉。使用明确输入和结果类型，路由不承担完整存档流程。
7. 下载目标是现有 Pixiv 访问封装加 Requests，按资产流式写入；明确超时、有限重试、HTTP／业务状态、鉴权与 URL 失效；单图、多页、动图及失败契约通过后才替换 gallery-dl。
8. 阻塞 I/O 放在受控同步边界，采用短事务和明确生命周期；不引入微服务或两套同时写入的存档系统。

### 总进度、阶段与提示

| 状态／动作 | 可见反馈与约束 |
| --- | --- |
| 提交 | 返回任务标识及新建／复用结果，说明排队或运行，可定位具体任务 |
| 本轮清点 | 固定本轮任务范围，确定处理清单；显示已检查数量及可靠的阶段进度，未知总量不编百分比 |
| 执行 | 默认一条本轮总进度，展开各任务及阶段；分母固定，重试不重复计数 |
| 中途新增 | 进入下一轮，显示等待数量，不追加当前分母、不令当前百分比倒退 |
| 阶段切换 | 名称、单位、总量、完成量与详情原子更新；前端渲染后台状态，不猜阶段 |
| 结果 | 总进度按已有处理结论的清单项推进；成功、失败、跳过及未执行分开，100% 不等于全部成功；空清单显示无需处理 |
| 通知 | 普通成功轻提示，异常持续标记；结果持久化，重启可看，关闭提示不删除记录 |
| 连接中断 | 显示暂时无法获取状态和最后更新时间，恢复后重读；不把断连认作任务结束 |
| 全部结束 | 更新结果和新增内容提示，不整页刷新、不抢阅读位置 |

接口至少承载任务提交结果、轮次、任务／阶段快照、处理项结果、下一轮数量和资产状态。各阶段分别用画师、作品、页或字节计量；清点失败不能当作无新作或检查完整。

## v0.2.0 执行包：普通阅览与流式阅览

### 入口、操作与状态

| 模式 | 行为 |
| --- | --- |
| 网格 | 默认入口，同尺寸裁切卡片；沿用筛选排序及滚动／页码模式；普通点击进入普通阅览，另设流式入口 |
| 普通阅览 | 左右换作品，上下读当前作品所有页面；先完整显示，按需缩放；常用操作可达，说明和整理功能可展开 |
| 流式阅览 | 当前图库／筛选范围内自然纵向连续，不强制整屏吸附；多页全展开后接下一作品，有跳过当前作品按钮；不横向换作品 |

普通和流式独立保存位置，按设备／浏览器记忆，不做跨设备接力。锚点为作品 ID、页号和偏移；从第 20 件看至第 35 件后返回定位第 35 件。浏览器历史恢复对应模式、筛选和位置。

方向键与按钮共用导航，输入框内不抢按键，连续操作不造成乱序；触控锁定方向，多指、缩放和控件操作不换作品。切换保留当前画面至目标可呈现，再短过渡；失败原位重试。后台新增不强制重排或刷新当前阅读。

### 数据接口与性能实现

1. 查询统一筛选、排序、分页、相邻作品和定位；保留空选／全选、类型、日期和 Tag 语义，不在每次阅读时取全库 ID。
2. 查询标识和请求代次拒绝旧响应，取消过时请求；加载、空结果、断连及部分媒体失败均可恢复。
3. 缩略图按稳定作品／页 ID、源版本和规格缓存，后台有界生成；冷图库先显示首屏，不等全库建图，原件不覆盖。
4. 使用 @tanstack/vue-virtual；网格按行，流式按图片页，不把整部多页作品作为巨大虚拟项。
5. 附近内容有限预取，远处媒体释放，图片尺寸占位与滚动锚点稳定；覆盖动态高度、长图和 GIF。
6. 可遍历整个图库，不靠 MAX_VISIBLE_ITEMS 截断浏览解决卡顿。
7. 入口为现有 works 路由、图库／详情模板、样式和构建配置；新前端目录先在 AGENTS.md 定用途、产物和清理边界。

4. **并行：** 检查、资产下载、派生生成／维护分开调度并设置资源上限，共用远端限流；同一资产不能并发重复执行，动图按原包→预览→缩略图依赖处理，删除意图继续压过旧任务。文件发布和数据库更新维持一致性，不能直接复制现有整轮 worker。

   2026-09-29 [访问限制调查](审查/2026-09-29-原图下载与状态诊断.md)补充：BUG-072 的 HTTP 429 与正文限流处理不一致已隔离复现；“每秒一次”不是官方安全保证。上述请求冷却、脱敏原因保留及 BUG-071 状态覆盖已在构建 20260929.3 修复并隔离验证；R-061 的完整并行执行器当时仍属候选，其后已在构建 20260930.2 实施，见本轮交付记录。
5. **真实进度：** 核验先列出要检查的记录，再把每项实际核验计入执行；已完成的检查／下载／核验数量有固定单位，重试不重复计数。展示当前任务，不再等待所有并行任务确定一个总分母；有新资产时形成下一固定批次，明确切换名称而不悄悄改变分母。
6. **浮层焦点：** 优先跟随用户主动发起的任务；无新主动操作时固定跟随当前任务直到结束，再切下一个，避免因后台轮询不断跳名。其他通道仅一行说明正在做什么；未知总量明确写已处理数。
7. **结果与日志：** 成功／普通信息自动消失；错误提示不永久覆盖画面，相关页面保留可恢复入口、日志保留原因。前台删除任务记录入口，内部的任务标识、恢复、去重和结果记录保留。确认用户决定的对话框不当作会自动关闭的通知。
8. **暂停与恢复：** 保留已开始自动批次全部完成、后续批次等待恢复的决定；手动操作可执行。并行后按批次范围固定此语义，不因通道拆分而中断已开始批次。
