### 实现顺序与模块边界

1. **先固定契约与验收场景。** 为上表逐项登记输入、状态、失败反馈、接口及源码／EXE／真实设备证据。先约定作品、版本、媒体、阅读会话和任务控制的边界；保留现有 Python／FastAPI／SQLite／Vue／托盘形态，不重新选整套框架。
2. **完成数据兼容、启动与任务基础。** 隔离结构转换先行；补单例／就绪；将长检查拆成能让出和恢复的小步骤，再改候选查询、调度、暂停与日志。版本存档与阅览均依赖这一层，不靠增加无限线程掩盖阻塞。
3. **完成版本存档及统一维护。** 接通完整／缺页旧档、多页增减、图片替换、纯资料变化、动图原包／时序、单件内容比对、来源事实与缺项恢复。完成删除与晚到结果保护后再开放历史版本界面。
4. **完成阅览和日常管理。** 以固定版本和范围接随机流式、手势、上下件、整理连续性、缓存；完成画师、筛选、来源清单、周期、添加身份预览和手机入口。独立页面可在契约确定后并行开发，最终同包集成。
5. **整包验收与交付。** 主会话先走查完整日常流程；源码、浏览器和独立 EXE 分层验证通过后，才交付本轮统一候选。真实库接入、限定账号测试及电脑／实体手机验收接续完成，未通过者保持未验收。

主会话负责设计、接口、范围表、跨模块审查、集成及交付；较大独立范围交 GPT-6.1 Sol high 子代理，小改动自行处理。子代理不可自行扩大 schema、账号、发布或真实数据范围。内部里程碑服务于集成，不变成面向用户的多个零碎交付包。

### 任务、进度与暂停

- **入口：** `core/tasks.py`、`core/database.py`、`core/archive.py`、`core/reconcile.py`、`client.py`、`core/download.py`、`scheduler.py`、任务 API 与进度组件。
- **领取：** 先选择可执行操作，再按索引读取有界候选；依赖键精确查找，避免每个候选扫描整个操作。保留领取的原子校验、资源互斥及删除意图检查；网络、散列、媒体解码不在数据库写事务内。采用实际查询计划与规模结果选择实现，不能照抄审查探针中的 SQL 当验收。
- **公平：** 按操作轮转并给用户主动小操作优先机会，同时保证大维护持续前进。常规检查、全库维护、收藏核对都受共同远端限速；有优先级不代表绕过限流。
- **拆分：** 日常 `check.plan()` 当前会扫完整个选择范围，`bookmark_artist` 会读全位画师，均改为分页／有限作品批次。保存清点范围、分页进度与去重结果，避免把大循环换一个函数名后仍占住工作者。详情与动图时序调用、连接重试分为可调度步骤，等待冷却不占着执行线程。
- **暂停：** 接受后立即显示“正在暂停”，阻止该操作再领取；网络调用使用有限超时和取消检查，下载在数据块边界停止并保留受控临时产物；已开始的原子发布／数据库提交完成后停。未完整文件不能计成功。显示已暂停后，可继续剩余工作；不支持安全续传时最多重新取得该未完成文件，不能重做已核验成功的文件或整轮。
- **恢复：** 控制意图、清点游标、处理项与阶段结果持久保存；重启保持手动暂停，未完成收藏先回读、不重放写入。已开始自动批次继续完成，后续自动批次按最新暂停设置取名单；全局退出不等待全部队列耗尽。
- **反馈：** 保留一条浮动当前任务进度与并行工作简述，未知总量明确正在清点；暂停／继续出现在相关维护状态处，设置保留入口。成功、失败、跳过和未执行分开；结束不刷新阅读页；状态连接中断明确表达。只保留日志入口与内部恢复记录，不恢复前台任务历史页。
- **日志：** 使用构建号、操作／步骤 ID 关联领取、写锁、远端等待、文件处理耗时与安全错误类别；不得记录凭据或带敏感参数的完整远端 URL。

### 版本存档与资料变化

- **身份：** 保持一个 Pixiv 作品对应一个作品身份；本地隐藏、评分、追踪关系和主站收藏仍属于作品。版本是其下的不可变快照，媒体文件通过引用归属版本，不能复制 Work 来模拟新版本。
- **候选结构：** 增加作品版本及版本媒体清单／引用；实际原件与派生有独立稳定身份，相同已核验内容可被同作品多个版本引用。现有资产 ID、媒体路径、恢复记录和删除意图必须映射；现有 `(work_id, role, page_index)` 等唯一约束不能直接用于多版本。当前 Work 的标题／标签等兼容字段作为所选默认版本的投影，写入由同一服务完成。
- **变化：** 规范化标题、简介、标签等快照字段，过滤无意义格式差异；页数、页序、类型、图片内容及动图时序参与版本判定，收藏／浏览数、最近检查时间和本地状态不参与。标题等变更也保留版本；重复观测同一状态不重复建版。再次恢复为以前的内容，保留新观察时间及变化记录，复用相同文件。
- **确认：** 页数／有序地址／时序变化触发候选；地址变化只是线索，实际取得内容后核验，纯地址变化且内容相同不产生假图片版本。资料缺字段、明确空值和临时读取失败分开，失败不生成空资料版本。无变化线索的旧作不全库重下；单件“重新比对原图”在作品管理区，说明会重新取得该作品文件，失败保留旧档与原因。
- **纯资料版本：** 没有媒体变化线索时直接引用已存媒体，记录为沿用本地内容，不声称重新核实过主站字节；不能因为改了标题或标签就重新下载全件。媒体有变化线索或用户指定内容比对时，再取得并核对相关文件。
- **保存：** 新版先建立固定来源清单，再逐项取得、校验及发布；只有能证明对应同一来源内容的旧文件才能复用，不能把旧版第一页与未经比对的新后续页拼成完整新版。过程中主站又变更时保留已得内容和候选记录，重新明确目标，不强行宣布完整。
- **可用性：** 本地可看、原件完整、预览就绪分开。新版原件完整且可呈现后才成为默认；原件未齐／转换失败保留旧版，展示具体缺口。没有完整版本的作品仍显示已有可看内容，不能从图库消失；旧 GIF-only 继续可看，不因此谎称 ZIP 完整。
- **展示：** 图库／流式每件作品一张卡，统计不因历史版本增加作品数；详情提供版本时间和变化摘要、显式切换。现有阅读绑定打开时版本，同版本补图允许原位更新，后台新版本不能换当前画面。
- **资料与收藏：** 历史版本展示当时标题、简介、标签及主站译名；收藏仍表示当前账号对同一个 Pixiv 作品的事实，不能切历史版本就回到旧收藏状态。来源可访问性与本地版本完整性分别呈现。
- **删除：** 现有“删除作品”继续作用于整件本地作品及其历史版本，确认界面说明范围；共享文件只在没有任何保留引用时处理，删除意图优先于晚到的版本下载／发布。取消隐藏／收藏操作不产生内容版本，不引入自动清理历史版本。

### 阅读范围、随机与交互

- **入口：** `core/library.py`、阅览 API、`App.vue`、`PageReader.vue`、`MediaImage.vue`、`ZoomView.vue` 及浏览器状态模块；图库、相邻定位和流式仍共用筛选语义。
- **固定范围：** 为本次阅览固定轻量作品 ID／版本 ID 顺序清单，按窗口取得页面资料；当前仅有 ceiling／as_of 不足以保证标题／标签变化后仍不重排。新内容在重新进入或明确刷新范围时读取，当前会话不突然插队；隐藏／删除按身份跳过，保留其他作品相对顺序。
- **随机轮次：** 同一次阅览基于固定成员与随机种子，按轮次生成可重建的排列；上一件能返回实际经过的顺序，越过轮次边界也不重新抽签。每件多页连续展开。新一轮有轻提示，超过一件时避免边界紧接同一件；空范围不空转，单件不不断重新请求同一文件。
- **有界资源：** 轻量成员清单不包含完整作品／图片数据；连续图库最多保留 480 件、阅览最多 120 页元数据，媒体与预取另设有限窗口。页码模式的 500 件／页仍全部可达，按行虚拟化与有限媒体验证，不用连续窗口上限截断这一页。轮次可重建，不为每轮积累整套图片元数据；活动阅读会话有限并可释放，不写入跨页面／会话最后位置记录。
- **模式与导航：** 模式偏好可以保存，重进从头开始；同次切换顺序／随机尽量围绕当前作品继续，不打断其多页。按钮、方向键与手势共用导航，目标失败保留当前画面；隐藏／删除先确定下一作品身份，再更新列表，末尾给出到头／空范围状态，不误跳两件。
- **触控：** 单击与双击由一个识别器仲裁；等待双击窗口期间不给单击重复开层，滚动／多指／控件操作取消图片点击。流式双击只表达收藏，角落动画是点击反馈，真实红心仍遵守主站确认；缩放层双击在适屏与放大倍率间调整并围绕点击位置，关闭回到当前图位置。实机手感最终单独验收。
- **缓存：** 条件请求基于实际媒体版本，鉴权与路径检查在返回 304 前完成；原件不可被缓存缩略图覆盖。详情缓存以作品＋版本标识，有界去重；账号变化只使相关收藏事实失效，资料与可见媒体不全量清空。旧请求不能覆盖新筛选或新版本。

### 日常管理与视觉

- **来源一览：** 采用“主站已无法访问”，不再并列无实际闭环的确认分类。401／429／503、超时和首次未知不认定来源失效；旧弱证据记录不能批量升级成删除事实。画师头像警示与同一有效事实一致；日志保留本次核对失败，主页和阅读画面不加来源横幅。

## 0.2.0 内部构建 20260929.2：试用阻断问题修订

状态：已实施并交付本地内部构建；源码、浏览器、EXE 验证通过，用户体验待复验。证据见[B 试用问题修订](审查/2026-09-29-B试用问题修订.md)。

- **使用问题：** Logo 与设置图标偏斜；设置页无法滚到下方；无缩略图时长期显示准备中，作品曾短暂消失后恢复；已收藏作品重新加载后全部空心。
- **界面修正：** 居中且尺寸稳定的矢量 Logo／设置图标；设置和画师页拥有可用的独立滚动区域，手机能到达底部操作。
- **卡片与缩略图：** 首先忠实呈现本地文件状态；没有可用首图时不反复提交必败缩略图任务。有可用本地原图时按可见范围临时显示首图；缩略图成功后接替。缩略图提交或生成失败不阻断图库读取和连续浏览，保留可重试反馈，图片缺失不能删除或隐藏作品。
- **收藏：** 同账号已确认的本地事实可立即显示，缓存过期不把已收藏改为空心；账号不明或不匹配不得用旧值生成写入意图。新收藏／取消仍以主站回读为准，待核对期间保留最后确认事实，不乐观变红；相关入口共用状态。
- **实现与边界：** 在现有 Vue 组件、只读图库投影和收藏服务上做兼容修订；不改数据库结构，不迁移／删除真实文件，不修改令牌，不自动重试真实账号下载或收藏。真实下载拒绝原因单独核查，不能以修复缩略图显示冒充原件已经下载。
- **验证：** 图标几何与实际截图、桌面／390／320px 设置滚到底、缺缩略图与缺原件分别复现、生成失败仍可连续浏览、原图兜底有界；收藏覆盖缓存过期、同账号／换号、待确认、旧响应与原读回约束。交付独立内部构建，公开版本继续为 0.2.0。

后续审阅重点是 B 接回完整功能后仍保持舒适，用同一批实际作品比较现版与候选，覆盖长标题、多页及任务浮层。当前示意图色彩和内容较统一，可能也影响安静感；共用灰阶、减少强调和稳定间距是设计判断，尚未单独验证各因素的作用。

- 深浅主题的大面积底色采用中性灰阶，降低现有蓝灰底的存在感；Pixiv 蓝集中在品牌、当前选中和关键操作，文字仍须清楚可读。
- 收敛顶部装饰蓝线、实心导航胶囊、重复大标题、计数与说明；导航退居图片周边，信息通过字号和间距分级。
- 统一卡片、图片与文字的对齐和间距，降低普通边框／阴影的存在感；分级、页数和红心保留，但各自大小与强调程度按实际作用安排。
- 普通阅览和流式在停手后保持稳定；换图保留短过渡，主题切换保留柔和效果，减少无必要的循环动画、跳动和反复弹出。

- 用同一批作品、同一窗口对照旧版和候选，覆盖密集网格、多页、长图、深浅主题、手机与后台有任务；验收关注视线是否自然落到画作、连续浏览是否被控件吸引，以及功能是否仍容易找到。历史截图素材不同，只能支持界面结构比较。

### 用户问题与范围

处理缺页仍报完整、失败仍报成功、原包丢失、暂停／停止混同，以及总进度像指示灯、状态和结果难以追溯的问题。覆盖现有添加、检查、刷新、补下载、单件下载、校验与本地整理入口，先接回现有界面。Vue 阅览界面与新工具不进入本版。

### 业务核心与数据规则

1. 画师身份独立于追踪；本地浏览、隐藏、删除不依赖登录。停止追踪保留文件、元数据与本地选择。
2. 自动检查任务开始时固定本批画师名单；中途暂停不改变该已启动批次，尚未启动的自动批次读取最新政策；手动操作不以自动暂停状态拒绝执行。
3. 按作品与页号／原包记录资产、路径与核验状态；缺页、空文件、损坏和预览失败分别报告，非空 file_paths 不等于完整。
4. 动图 ZIP、帧顺序和时长长期保留；GIF 发布前核验可读性及时序，失败保源。旧 GIF 不删除，缺原包清单由用户选择补齐。
5. 下载与转换先暂存、再校验发布；文件发布、DB 更新和删除决定有恢复记录。重启核对未完成项，成功项不重复下载，发布前再次检查删除阻止记录。
6. 按操作目的、目标和范围去重；不同目的不可因画师 ID 相同而互相吞掉。使用明确输入和结果类型，路由不承担完整存档流程。
7. 下载目标是现有 Pixiv 访问封装加 Requests，按资产流式写入；明确超时、有限重试、HTTP／业务状态、鉴权与 URL 失效；单图、多页、动图及失败契约通过后才替换 gallery-dl。
8. 阻塞 I/O 放在受控同步边界，采用短事务和明确生命周期；不引入微服务或两套同时写入的存档系统。

| 状态／动作 | 可见反馈与约束 |

| 连接中断 | 显示暂时无法获取状态和最后更新时间，恢复后重读；不把断连认作任务结束 |
| 全部结束 | 更新结果和新增内容提示，不整页刷新、不抢阅读位置 |

接口至少承载任务提交结果、轮次、任务／阶段快照、处理项结果、下一轮数量和资产状态。各阶段分别用画师、作品、页或字节计量；清点失败不能当作无新作或检查完整。

### 必须通过的验收

## v0.2.0 执行包：普通阅览与流式阅览

**前置与状态：** v0.1.2 存档和任务接口已通过隔离可靠性验收；真实图库已由 v0.2.1 完成转换并离线运行，但用户明确判定 v0.2.1 的视觉体验不通过，因此该版阅览交付未验收。联网功能仍另行验收。v0.2.0 已将 Vue 3 + TypeScript 构建产物随候选 EXE 分发，资源不依赖外部 CDN；隔离验证与切换结果分别见对应实施记录。

### 入口、操作与状态

| 模式 | 行为 |
| --- | --- |
| 网格 | 默认入口，同尺寸裁切卡片；沿用筛选排序及滚动／页码模式；普通点击进入普通阅览，另设流式入口 |
| 普通阅览 | 左右换作品，上下读当前作品所有页面；先完整显示，按需缩放；常用操作可达，说明和整理功能可展开 |
| 流式阅览 | 当前图库／筛选范围内自然纵向连续，不强制整屏吸附；多页全展开后接下一作品，有跳过当前作品按钮；不横向换作品 |
| 放大查看层 | 保留来源模式和位置，支持缩放和平移，关闭回原位，缩放时不触发换作品 |

普通和流式独立保存位置，按设备／浏览器记忆，不做跨设备接力。锚点为作品 ID、页号和偏移；从第 20 件看至第 35 件后返回定位第 35 件。浏览器历史恢复对应模式、筛选和位置。

方向键与按钮共用导航，输入框内不抢按键，连续操作不造成乱序；触控锁定方向，多指、缩放和控件操作不换作品。切换保留当前画面至目标可呈现，再短过渡；失败原位重试。后台新增不强制重排或刷新当前阅读。

### 数据接口与性能实现

1. 查询统一筛选、排序、分页、相邻作品和定位；保留空选／全选、类型、日期和 Tag 语义，不在每次阅读时取全库 ID。
2. 查询标识和请求代次拒绝旧响应，取消过时请求；加载、空结果、断连及部分媒体失败均可恢复。
3. 缩略图按稳定作品／页 ID、源版本和规格缓存，后台有界生成；冷图库先显示首屏，不等全库建图，原件不覆盖。
4. 使用 @tanstack/vue-virtual；网格按行，流式按图片页，不把整部多页作品作为巨大虚拟项。
5. 附近内容有限预取，远处媒体释放，图片尺寸占位与滚动锚点稳定；覆盖动态高度、长图和 GIF。
6. 可遍历整个图库，不靠 MAX_VISIBLE_ITEMS 截断浏览解决卡顿。
7. 入口为现有 works 路由、图库／详情模板、样式和构建配置；新前端目录先在 AGENTS.md 定用途、产物和清理边界。

### 必须通过的验收

- 桌面按钮／方向键与真实手机纵向、横向、斜向、多指、缩放、连续操作；手机尺寸的桌面窗口不能代替实机。
- 20→35 返回锚点、模式隔离、放大关闭回原位、前进／后退、筛选空结果恢复、慢响应乱序。
- 多页展开、长作品跳过、长图、动图、媒体失败重试；换作品及后台任务结束均不整页刷新。

### 后台状态与实现约束

1. **程序实例：** 在启动日志、网络服务与托盘之前取得单实例资格；重复启动使用已有实例实际端口打开界面，启动失败收尾，崩溃退出后可再次启动。图库租约继续独立保护数据，不能只根据进程名或端口占用判断是本程序。
2. **轻量检查：** 检查负责发现新作品和保存必要信息，后续下载针对确定的资产；不遍历体检全部已有原件、动图和缩略图。已知失败项保留重试入口，未知旧文件保留未知，不顺带强制核验或批量补原包。
3. **远端完整性：** 先消除本地全量清点与重复写入；远端分页优化以接口顺序和边界证据为前提，不能遇到第一件旧作品就终止。新增、分页变动、不可用作品恢复和检查中断不得漏检。
4. **并行：** 检查、资产下载、派生生成／维护分开调度并设置资源上限，共用远端限流；同一资产不能并发重复执行，动图按原包→预览→缩略图依赖处理，删除意图继续压过旧任务。文件发布和数据库更新维持一致性，不能直接复制现有整轮 worker。

   2026-09-29 [访问限制调查](审查/2026-09-29-原图下载与状态诊断.md)补充：BUG-072 的 HTTP 429 与正文限流处理不一致已隔离复现；“每秒一次”不是官方安全保证。上述请求冷却、脱敏原因保留及 BUG-071 状态覆盖已在构建 20260929.3 修复并隔离验证；R-061 的完整并行执行器当时仍属候选，其后已在构建 20260930.2 实施，见本轮交付记录。
5. **真实进度：** 核验先列出要检查的记录，再把每项实际核验计入执行；已完成的检查／下载／核验数量有固定单位，重试不重复计数。展示当前任务，不再等待所有并行任务确定一个总分母；有新资产时形成下一固定批次，明确切换名称而不悄悄改变分母。
6. **浮层焦点：** 优先跟随用户主动发起的任务；无新主动操作时固定跟随当前任务直到结束，再切下一个，避免因后台轮询不断跳名。其他通道仅一行说明正在做什么；未知总量明确写已处理数。
7. **结果与日志：** 成功／普通信息自动消失；错误提示不永久覆盖画面，相关页面保留可恢复入口、日志保留原因。前台删除任务记录入口，内部的任务标识、恢复、去重和结果记录保留。确认用户决定的对话框不当作会自动关闭的通知。
8. **暂停与恢复：** 保留已开始自动批次全部完成、后续批次等待恢复的决定；手动操作可执行。并行后按批次范围固定此语义，不因通道拆分而中断已开始批次。
