## 先看这一页

本项目的最新愿景，由 Scathiard 于 2026-09-07 定义：

> 一个第三方 Pixiv 工具，旨在满足自动下载存档喜爱画师的作品这一基本功能的前提下，成为能媲美甚至部分超越原版 Pixiv 使用体验的第三方客户端。

**本项目自始至终本地优先：可靠存档喜爱画师的作品，并让电脑和手机上的本地阅览足够顺畅。** “媲美或部分超越 Pixiv”指使用体验，不意味着建设在线搜索、推荐、排行榜或在线作品流。此前文档将在线客户端推导为主线，是主策划的理解偏差，本次纠正；不是用户曾批准在线主线后再转向。

**美观与可靠同等重要，分别验收；任一方面未通过，版本就不算通过。** 美观涵盖图库、普通阅览和流式阅览的画面层级、作品呈现、排版、控件与动效，不能只用“功能可点通”或浏览器无报错代替。2026-09-27 用户明确判定 v0.2.1 的当前视觉体验不通过；数据转换与运行验证结果仍有效，但不构成该版本的产品验收。

追踪和下载所需联网、已有 Pixiv 收藏操作继续保留；联网小工具可以单独讨论，但不能成为使用本地图库的前置条件。断网或登录失效时，已存内容仍应可浏览、筛选和整理。

**存档的核心目的之一，是在画师删除主站作品后仍保有作品。** 用户于 2026-09-29 重申，这是项目诞生的初衷。本地存档完整性与主站是否还能获取必须分别判断；主站删稿或不可访问不能使已有本地文件、简介、标签和整理信息被删除、隐藏或清空，也不能把完整存档判作失败。未存下的内容仍须如实标明缺失，不能承诺能够补回；一次 404 只能说明本次请求未取得内容，不能直接断言画师已删除作品。

2026-09-26 用户要求落实《本地优先的项目接手与两阶段交付方案》：先存档与反馈可靠，再交付普通阅览和独立流式阅览。具体实施状态、额外授权与验收统一见[功能路线图](功能路线图.md)，不能把产品定案写成代码已完成。

## 希望用户完成的过程

### 1. 选择喜欢的画师，之后持续收到作品

用户找到画师，决定将其纳入自动存档。程序应说明首次需要处理什么、正在做什么、是否遇到问题。后续检查与下载应持续工作，用户不需要靠反复点刷新来维持存档。

现有功能已经覆盖这条流程的主要步骤。近期重点是让状态可信、失败可理解，并验证补下载不会漏掉缺失页面。

### 2. 舒服地浏览已经保存的作品

打开程序后从当前范围开头看到内容；从列表进入详情，返回保留筛选并回到顶部；不因上次翻得很深而妨碍查看最新作品。多页作品、动图、简介和画师信息应该形成连续的阅读过程。电脑上的鼠标键盘操作与手机上的触摸操作都要成立。

这是主策划建议优先建立优势的部分：本地图库可控、跨画师检索方便、长期回看稳定。具体速度指标先建立实际图库和设备基线，再写入版本验收。

### 3. 连续浏览本地图库

网格用于挑选作品，普通阅览用于仔细看一件作品，流式阅览用于纵向连续看整个图库或当前筛选结果。三者入口明确，普通与流式保留各自当前阅览的临时状态，离开后不记忆最后位置；流式不会把网格的普通点击行为改掉。

普通阅览默认先完整显示图片，需要时放大；流式自然滚动，不做整屏强制吸附。进入放大层时保留来源位置，退出后继续原来的阅读。

### 4. 理解和管理自己的收藏

逐步支持批量整理、个人评分、统计、备份恢复等能力。用户应能知道哪些内容来自 Pixiv，哪些是自己在本地作的决定，以及删除、取消收藏、停止追踪各自会影响什么。

## 术语先分清

| 术语 | 当前含义／讨论约束 |
| --- | --- |
| 特别关注／追踪 | 本工具的自动存档名单；不默认等于用户在 Pixiv 上关注的全部画师 |
| Pixiv 收藏 | 会改变 Pixiv 账号上作品的收藏状态；当前实现与本地隐藏是两种操作 |
| 本地存档 | 用户希望长期保留的文件及相关信息；远端作品不可用时，已有本地内容仍有独立价值 |
| 缓存 | 为显示或计算临时保存、允许重建的内容；新缓存策略尚待设计 |
| 作品与页面 | 一件作品可能包含多张图片，统计“作品数”和“文件／页数”必须注明单位 |
| 作品简介 | Pixiv 作品的 caption；不等于画师个人简介 |
| 隐藏 | 改变本地展示状态；不等于删除文件，也不等于取消 Pixiv 收藏 |
| 暂停追踪 | 只暂停后续自动检查，不移出本地图库、不禁止手动操作；已启动批次完成 |
| 停止追踪 | 移出自动追踪名单，保留身份、作品、文件和本地选择；删除需独立明确操作 |
| 流式阅览 | 本地图库或当前筛选范围的连续纵向阅读，不是在线推荐信息流 |
| 进度轮次 | 本轮清点后固定的任务与处理项集合；后来加入的任务排下一轮 |
| 完成 | 必须指明完成了哪一项：代码、测试、打包、用户验收或远端发布，不能混用 |

## 设计讨论的判断标准

下列是主策划建议采用的评估标准；进入具体版本时需落实为能复现的验收条件。

| 方面 | 讨论时要回答的问题 |
| --- | --- |
| 存档可靠性 | 新作、补下载、断网、远端删除、重试时，哪些文件和本地决定必须留下？如何发现缺损？ |
| 浏览体验 | 用户找到并看完想看的内容要经过哪些步骤？返回、翻页、缩放、滚动是否打断阅读？ |
| 状态反馈 | 现在在检查、下载、转换还是等待？失败了多少？需要用户做什么？ |
| 性能 | 大图库、机械硬盘、手机和较慢网络分别慢在哪里？优化是否增加漏检或误删的可能？ |
| 操作后果 | 点按钮后影响本地还是 Pixiv？能否撤销？确认提示是否准确说明损失？ |
| 维护成本 | 现有结构能否承担？新增依赖解决什么具体问题？安装、升级、失败与停用如何处理？ |

界面讨论要落实到入口、层级、文案、位置、尺寸与间距、鼠标／触屏／键盘动作，以及正常、加载、空白、失败、不可用状态。涉及图标和独立素材时，先写清用途和规格，再决定素材来源，不能仅用“优化 UI”作为任务说明。

## 架构方向的边界
