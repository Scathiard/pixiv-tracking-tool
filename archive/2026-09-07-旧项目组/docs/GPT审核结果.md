## 已确认问题

### P0 - `/images` 路径穿越，可读取目录外文件

**位置：** `app/src/web.py:133-139`

**现象：** 图片服务将 URL 路径直接拼接到 `IMAGES_DIR`，仅检查目标是否存在，未确认解析后的最终路径仍在图片目录内。经编码的 `..` 路径可越出图片目录。

**影响：** 在默认数据结构下，局域网访问者可读取 `data/pixiv_token.json`、`.env` 等文件；这超出“可完整操作应用”的既定授权范围，并可能导致 Pixiv 账号 token 泄露。

**修复方向：** 解析并规范化目标路径，验证其仍是 `IMAGES_DIR` 的子路径；拒绝绝对路径、`..` 跳转和符号链接越界。

### P1 - 数据目录迁移可与后台任务并发，存在数据分裂或丢失风险

**位置：** `app/src/config.py:115-171`、`app/src/routes/settings.py:71-83`

**现象：** 数据迁移会复制数据库、移动图片并立即切换全局数据路径，但未等待下载、同步、转换或其他后台任务结束，也没有互斥锁、完整性验证或失败回滚。

**影响：** 迁移过程中新增或移动的文件可能落在旧目录或新目录的一侧；目标目录已有同名文件时会被跳过，程序仍会切换到新目录，造成数据库与图片不一致。将目标选在旧数据目录内部还可能造成递归复制。

**修复方向：** 迁移前禁止新任务并等待活动任务结束；使用单一迁移锁、临时目录、清单校验和原子切换；拒绝目标目录位于当前数据目录内部。

### P1 - 同步和下载任务存在全局资源竞态

**位置：** `app/src/tracker.py:686-744`、`app/src/routes/settings.py:38-67`、`app/src/routes/artists.py:122-206`

**现象：** 手动检查、补下载、单画师刷新、添加画师后的抓取和定时任务均可创建后台线程；多个下载任务共享 `gallery-dl` 全局配置及同一个 `gallery_dl_archive.db`，部分流程还会删除该归档文件。

**影响：** 并发操作可能互相清除下载去重记录、重复下载、漏记文件、触发 SQLite 锁错误，或令进度状态与实际任务不一致。

**修复方向：** 将会写数据库、下载目录和 `gallery-dl` 配置的操作串行化为单一任务队列；同类任务合并或拒绝重复提交；迁移期间暂停队列。

### P2 - Pixiv caption 和进度错误信息存在 XSS 风险

**位置：** `app/src/tracker.py:48-59`、`app/src/templates/illust_detail.html:145-146`、`app/src/templates/base.html:152-156`

**现象：** caption 通过正则表达式清洗后使用 Jinja `safe` 渲染，无法可靠覆盖所有 HTML/URL 危险载荷；进度错误信息则直接拼入 `innerHTML`。

**影响：** 不可信的 Pixiv 文本或 API 错误内容可能执行浏览器端脚本、篡改界面或诱导跳转。局域网全权限模型下这不是额外的应用权限提升，但仍会破坏浏览器端安全边界。

**修复方向：** 使用成熟 HTML 白名单清洗器，只允许必要标签和安全 URL 协议；进度错误使用 `textContent` 或 DOM 节点创建，不使用 `innerHTML` 拼接。

### P2 - OAuth token 写入和日志处理不稳健

**位置：** `app/src/auth.py:64-81`、`app/src/auth.py:175`、`app/src/client.py:15-21`

**现象：** OAuth 客户端密钥和 hash secret 写入源码；OAuth authorization code 前缀会进入日志；token 文件直接覆盖写入，读取 JSON 的异常保护不完整。

**影响：** token 文件写入中断或内容损坏时，自动登录可能失败且不会顺畅进入恢复流程；日志扩大了短期授权码暴露面；源码中的固定密钥不利于凭据管理。

**修复方向：** token 采用临时文件加原子替换写入；损坏时安全回退到重新授权；日志不记录 authorization code；评估并迁移硬编码凭据的管理方式。

### P2 - 发布链路不可复现

**位置：** `app/release.bat:21`、`app/build.spec:26`、`app/requirements.txt`

**现象：** 发布脚本要求复制 `app/.env.example`，但该文件不存在；依赖仅声明最低版本且未锁定；PyInstaller 输出版本号依赖手工修改 spec 文件。当前 `release/v0.1.0` 为未跟踪发布物。

**影响：** 从仓库重新构建时发布脚本会失败，或在依赖升级后得到不同结果，无法可靠复现已发布版本。

**修复方向：** 补齐可提交的脱敏 `.env.example`；固定依赖版本或提供 lock 文件；将版本号集中管理，并在构建前校验发布目录与版本一致性。

### P2 - 缺少自动化测试与正式规则入口

**位置：** 项目根目录、`app/`

**现象：** 未发现测试目录或测试文件；根目录现有 `claude.md`，但没有正式 `AGENTS.md`。

**影响：** 高风险的文件迁移、并发下载、路由安全和发布过程无法防回归；项目规范入口与当前协作约束不一致。

**修复方向：** 先建立 `AGENTS.md` 作为唯一规则入口；为路径隔离、迁移事务、任务互斥、路由输入验证和发布脚本补充自动化测试。
