原始文件只搬存，不改写其中结论。新发现、更正和当前状态写入现行文档；不要修饰旧资料使它看起来一直正确。

原文中的相对路径仍按旧工作区解释，必要时依据本索引和搬迁清单定位；不为修复历史链接而修改原文。

`workspace/` 由根 .gitignore 排除，可能包含私人配置、旧凭据和大型程序，不能加入 Git 或公开分发。原文档中的 .obsidian 配置同样沿用忽略规则。这里的归档不代替用户图库备份，也不设自动清理期限；任何删除仍须用户授权。

## 恢复方式

先查本批次清单与当前目录，确认目标不存在冲突后，再按原路径恢复选定文件。旧文档恢复为参考资料时不能覆盖当前三份主文档或团队通信。旧工作树通过 `git worktree move` 搬回，随后检查登记与未提交改动；不得只移动磁盘目录，也不要顺手执行 prune 或删除分支。

原根目录的开发测试令牌、源码默认 data／images、现有 .env、当前 app 实现和整个 release 均保留原位。用户正在使用的 v0.1.1 EXE 及其项目外图库不属于本批次搬迁范围。
